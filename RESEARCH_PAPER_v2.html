Abstract

Small and medium enterprises (SMEs) in retail and food service routinely collect transactional data through point-of-sale (POS) systems yet rarely leverage it for marketing decisions, primarily due to resource constraints and the technical complexity of existing analytics solutions. This paper presents a five-layer MLOps pipeline — the ML Campaign Engine — that transforms raw POS transaction records requiring only six standard fields into financially validated, per-customer campaign action plans without requiring a dedicated data science team. The framework integrates RFM-based customer segmentation (K-means with dynamic cluster selection via silhouette scoring, mapping to the IBM 10-segment standard via rank-percentile normalization, supplemented by four rule-based segment flags), market basket analysis (Apriori), data-driven temporal context detection, context-aware promotional cost routing, uplift modeling (LightGBM X-learner), and a local large language model (LLM) reporting layer.

Two novel architectural contributions distinguish this version from the initial framework. First, a hybrid IBM segmentation layer combines unsupervised K-means clustering (k ∈ {2,…,10}) with four deterministic rule-based flags — Can’t Lose Them, Churn Risk, About to Sleep, New Customer — applied post-clustering to guarantee critical customer states are always represented regardless of cluster geometry. A frequency trend feature (freq_trend = visit count in recent half-window minus early half-window) adaptively tightens flag thresholds for declining customers, surfacing churn risk 30% earlier than static recency alone. Second, a 2-step declarative decision engine replaces the original priority-rule cascade: Step 1 classifies each customer into an uplift group (sure_thing / persuadable / do_not_disturb / lost_cause) based on modeled treatment probability and uplift score; Step 2 selects the highest-profit action from a declarative rule library of 43 rules across all 10 IBM tiers. A configurable rescue tier mechanism relaxes the standard incremental-profit viability check to a loyalty-only baseline-profit check for high-value churning customers (Churn Risk, Can’t Lose Them, Hibernating, About to Sleep), ensuring retention investment is not blocked by incremental-uplift mathematics when the cost of losing a customer exceeds the promo cost. A zero-cost notification pathway serves high-value customers (RFM decile ≥ 7) for whom no promotional offer clears the profit floor, reinforcing loyalty with zero margin impact. The original CFO Guardrail mechanism enforces a configurable minimum net margin floor prior to campaign dispatch.

These architectural changes raised the campaign send rate from 8.9% to 50.1% on the production dessert restaurant dataset — a 5.6× improvement — while maintaining financial discipline: all send decisions remain subject to per-customer profit viability checks. The production Champion model (v7) is trained on a multi-store pool combining dessert restaurant transactions (proxy labels) with the Dunnhumby Complete Journey dataset (real causal labels), achieving Qini = 1.21 and a +3.56% gate improvement over the previous champion.

The framework is evaluated on seven datasets: (1) a synthetic restaurant POS dataset (9,344 line items, 200 customers; silhouette = 0.679; k = 2; 0/200 broadcast — zero validates calibration on randomized treatment); (2) a public marketing campaign dataset (905 customers; silhouette = 0.306; k = 3; 338/905 broadcast, Δprofit = $9,224); (3) the Dunnhumby Complete Journey grocery dataset (2,500 households, 2,576,815 rows; silhouette = 0.595; k = 3; 72/2,500 broadcast, Δprofit = $3,207); (4) a UK online retail dataset (397,884 line items, 4,338 customers; silhouette = 0.931; k = 2; 19/4,338 broadcast, Δprofit = $2,529); (5) a purpose-built Layer 3 synthetic test dataset (500 customers; engineered demand-surge products; validates context detection stockout suppression — 23/500 customers correctly blocked from campaign dispatch on out-of-stock items); (6) the Hillstrom MineThatData RCT (64,000 customers, three randomized arms), used to evaluate pooled multi-treatment uplift on true randomized labels — yielding Qini = 0.1215, AUUC = 0.0614, and ATE calibration error of 9% on the holdout; and (7) a production dessert restaurant POS dataset (dessert-ml.csv, 2,409 customers, 27,767 rows, ~11 months), used for Champion v7 training (multi-dataset pool with Dunnhumby), achieving Qini = 1.21 and +3.56% gate improvement. A consistent finding is that naive broadcast campaigns produce model-estimated incremental profit worse than running no campaign at all; the CFO Guardrail converts money-losing broadcast scenarios into net-positive outcomes. All profit figures are model-estimated projections on synthetic or public datasets. Results demonstrate robustness across F&B, grocery, and e-commerce contexts.

1. Introduction

Marketing personalization has become a competitive necessity in modern retail. Large enterprises routinely deploy dedicated analytics teams, expensive CRM platforms, and data warehouses to generate campaign recommendations at the individual customer level. For small and medium enterprises (SMEs) — which constitute the majority of businesses in most economies — this infrastructure remains economically and technically out of reach. The consequence is that SME operators make campaign decisions based on intuition or blanket promotions, systematically under-leveraging the transactional data they already possess.

This resource asymmetry creates a measurable market opportunity. POS systems are near-ubiquitous in modern retail and food service, and the transaction data they generate contains rich signals about customer value, product affinity, and purchasing patterns. If an automated pipeline could consume the POS export that any modern cash register already produces and return campaign actions validated against the operator’s own financial constraints, the marginal cost of personalized marketing could approach zero for SMEs.

The system described in this paper, referred to as the ML Campaign Engine, was designed to address this gap. Its design is governed by four principles:

  1. Minimal input barrier — the only required data is a standard six-column POS export (transaction_id, customer_id, timestamp, total_price, quantity, product_name). No additional data infrastructure, tagging, or transformation is required from the operator.
  2. Financial safety by default — every campaign recommendation is blocked if it violates a configurable net margin floor, decoupling ML optimization from financial risk without requiring a human review step.
  3. Operator-readable output — a local LLM layer translates model outputs into plain-language executive summaries suitable for business owners without a data background.
  4. Production-grade robustness — a Champion-Challenger update protocol and a six-scenario stress test suite ensure reliable behavior under distribution shifts common in SME operations.

1.1 Research Objectives

The primary objective of this work is:

To design and validate a minimal-input MLOps pipeline that enables SMEs in retail and food service to generate per-customer campaign action plans with integrated financial constraint validation, without requiring dedicated data science expertise.

Specific objectives are:

  1. To design a five-layer pipeline architecture (six layers in the extended production deployment including the campaign automation scheduler; five layers constitute the core ML pipeline) that accepts standard six-column POS exports without additional infrastructure requirements.
  2. To develop a CFO Guardrail mechanism that integrates net margin validation directly into the ML campaign decision loop.
  3. To evaluate segmentation quality and campaign profitability across seven datasets spanning synthetic F&B, marketing campaign, grocery retail, e-commerce, purpose-built Layer 3 test data, a true three-arm RCT, and a production dessert restaurant deployment.
  4. To describe and implement the Champion-Challenger model update protocol and assess its behavior on synthetic data, and ablate each pipeline component to quantify its individual contribution.
  5. To demonstrate the extensibility of the framework across business verticals through configurable business parameters.

1.2 Contributions

The primary contributions of this work are:

  • A five-layer MLOps architecture designed from the ground up for SME operational constraints (Section 3).
  • A CFO Guardrail component that integrates financial validation directly into the ML decision loop, eliminating a manual organizational review step (Section 4.4.6).
  • Hybrid IBM 10-segment customer segmentation combining unsupervised K-means clustering (k ∈ {2,…,10}, rank-percentile normalized to IBM standard names) with four deterministic rule-based flags (Can’t Lose Them, Churn Risk, About to Sleep, New Customer) applied post-clustering. This hybrid ensures critical high-value and churn-risk customer states are always reliably identified, regardless of K-means cluster geometry. Rule thresholds adapt via a frequency trend feature that tightens detection for declining customers (Section 4.1).
  • A 2-step declarative decision engine (Section 4.4.4–4.4.5): Step 1 classifies customers into uplift groups (sure_thing / persuadable / do_not_disturb / lost_cause) using modeled conversion probability and uplift score; Step 2 selects the highest-profit action from a library of 43 declarative rules covering all 10 IBM tiers across peak/off-peak contexts. This replaces a monolithic if/elif cascade with a maintainable, auditable rule structure that enables per-tier business logic without code changes.
  • A rescue tier mechanism with dual viability functions (Section 4.4.4): high-value churning customers (Churn Risk, Can’t Lose Them, Hibernating, About to Sleep) are routed through a loyalty-only baseline-profit viability check (_viable_loyalty) rather than the standard incremental-profit check (_viable). This prevents the standard incremental filter from suppressing retention investment for customers where the cost of churn exceeds the campaign cost.
  • A zero-cost notification pathway for high-value customers (RFM decile ≥ 7, tier in {Champions, Loyal, Can’t Lose Them, Potential Loyalist}) for whom no promotional offer clears the profit floor: a relationship message is dispatched at zero promo cost, reinforcing loyalty without margin impact (Section 4.4.4).
  • Data-driven temporal context detection with context-aware promotional cost routing: Layer 3 computes hourly transaction volume and sets peak-hour threshold = mean + 0.5×std, eliminating hardcoded peak-hour configuration. Layer 4 applies distinct promo cost rates per temporal context — 22% for Off-Peak customers (aggressive traffic driver during quiet periods) and 8% for Peak customers (light upsell when already visiting) — enabling financially optimized routing per customer’s behavioral pattern (Section 4.3, 4.4.4).
  • Campaign automation scheduler: A production scheduler (campaign_scheduler.py) implements a 3-wave monthly deployment strategy with 5% A/B holdout control group, per-customer send_datetime derived from detected peak windows, and templated messaging per action type — bridging Layer 4 decision outputs to CRM execution (Section 4.6).
  • Empirical evaluation on seven datasets (synthetic F&B, marketing campaign, Dunnhumby grocery, UK online retail, a purpose-built Layer 3 synthetic test dataset, the Hillstrom MineThatData RCT, and a production dessert restaurant POS dataset), including ablation study, cross-dataset baseline comparison, and multi-seed stability analysis (Section 6). AUUC on randomized labels: T-learner = 0.0612, X-learner = 0.0475 — both near-zero as expected for null treatment effect, validating calibration. Prior T-learner AUUC of 0.2351 was inflated by proxy label bias (Section 6.10.1).
  • A Champion-Challenger protocol adapted for SME environments with limited historical data (Section 4.4.7). Champion v7 uses multi-store pooling (dessert store + Dunnhumby) achieving Qini = 1.21 and +3.56% gate improvement.
  • Temporal-split proxy labels with leakage prevention (v1.15): When no real treatment/response data exists, proxy labels are derived from transaction timestamps (temporal retention signal) with random treatment assignment, and model features are restricted to basket-level signals that do not overlap with label construction — eliminating the feature-label circularity present in earlier RFM-rank proxy designs (Section 4.4.1).
  • Calibrated uplift probability estimates (v1.15): Base learners μ₀ and μ₁ are wrapped with CalibratedClassifierCV(isotonic, cv=3), reducing ECE by 87% (0.2496 → 0.0323) and producing reliable probability inputs to the CFO Guardrail profit formula (Section 4.4.1).
  • Post-campaign feedback loop (v1.15): holdout_evaluator.py ingests actual post-campaign outcomes, computes statistically-tested conversion lift with 95% confidence intervals, and exports retrain-ready labeled data compatible with Layer 4’s real label mode — closing the measurement loop from campaign deployment through model retraining (Section 4.6).
  • Budget-constrained campaign targeting (Section 4.4.8): A greedy knapsack optimizer (budget_optimizer.py) selects the profit-maximizing subset of CFO-approved customers within an operator-specified spend ceiling. Customers are ordered by bang-per-buck (expected_profit / promo_cost) and selected cumulatively — provably optimal for the fractional knapsack. For the 0/1 knapsack, the algorithm achieves at least a 1/2-approximation when combined with the option of selecting the single highest-profit customer as an alternative: max(greedy result, best single item) ≥ ½ × OPT — in O(n log n) time. When no budget ceiling is specified, all CFO-approved customers are selected unchanged. (Implementation complete; empirical validation against a real campaign with a fixed budget ceiling is pending.)
  • CLV-informed rescue tier viability (Section 4.4.9): A third viability function _viable_clv() conditions rescue campaign approval on promo_cost ≤ clv_at_risk — the expected revenue lost if the customer churns without intervention, estimated via a BG/NBD survival model (Beta-Geometric/Negative Binomial Distribution; Fader et al. 2005 [34]). This replaces the heuristic _viable_loyalty check for rescue tiers with a CLV-grounded financial justification. For high-frequency retail datasets where BG/NBD fails to converge (a known limitation for daily/weekly purchasing), the function falls back automatically to _viable_loyalty, preserving backward compatibility. (Implementation complete; BG/NBD falls back to heuristic on all tested datasets — dessert-ml and Dunnhumby — due to high purchase frequency. Empirical CLV results are pending.)
  • Pooled multi-treatment uplift on a true RCT (Section 4.4.10, 5.1, 6.11): A PooledMultiTreatmentModel trains a single X-learner with treatment arm encoded as one-hot features, sharing learning signal across arms rather than fitting separate one-vs-rest models. Evaluated on the Hillstrom MineThatData RCT [33] (64,000 customers, three balanced arms: no email / mens email / womens email). Results on holdout: Qini = 0.1215, AUUC = 0.0614, ATE calibration error of 9% (predicted +0.056 vs actual +0.062) — substantially lower than the 247% error observed under proxy-label training on retail datasets, where the absence of true randomization inflates apparent ATE discrepancy. Best-arm assignment: 68.7% mens email / 31.3% womens email, consistent with observed +7.7pp vs +4.5pp arm uplifts.

2. Related Work

2.1 RFM Segmentation

Recency-Frequency-Monetary (RFM) analysis is a well-established customer segmentation technique in direct marketing, originally formalized by Hughes [1] and subsequently refined for database marketing applications by Bult and Wansbeek [2]. Classical RFM assigns customers to decile ranks across each dimension; more recent work by Chen et al. [3] augments this with clustering algorithms to capture non-linear segment boundaries that decile ranking cannot express. Our Layer 1 extends classical RFM with K-means clustering [4] and dynamic cluster selection via silhouette scoring [5], and adds an IQR-based outlier filter [6] to prevent high-spend anomalies from distorting segment centroids — a practical concern in SME datasets where a single bulk transaction can represent a substantial fraction of total revenue. Cluster naming adopts the IBM 10-segment taxonomy (Champions, Loyal Customers, Potential Loyalist, Promising, Need Attention, About to Sleep, At-Risk, Can’t Lose Them, Hibernating, Lost) via rank-percentile normalization, supplemented by four deterministic rule-based flags that guarantee critical customer states are always represented regardless of cluster geometry.

2.2 Market Basket Analysis

Association rule mining, particularly the Apriori algorithm introduced by Agrawal and Srikant [7], has been widely applied in retail to identify product affinity. The algorithmic framework was later made accessible to practitioners through software implementations such as arules [8]. Prior work focuses largely on large-scale grocery and e-commerce datasets [9]. Application to SME food service and mixed retail — where transaction volumes are lower and basket sizes smaller — remains underexplored. Our Layer 2 addresses this by operating at a minimum support threshold of 0.01, appropriate for smaller datasets, and falls back gracefully when no product category column is present in the POS export.

2.3 Uplift Modeling

Uplift modeling (also called incremental response modeling or true-lift modeling) estimates the causal effect of a campaign on an individual customer, rather than the probability of conversion in the presence of a campaign — a distinction first formally articulated by Radcliffe and Surry [10]. A comprehensive review by Devriendt et al. [12] surveys the state of the art across tree-based, regression, and meta-learner approaches. Gutierrez and Gérardy [11] further connect uplift modeling to causal inference frameworks. Gradient boosted tree models, including XGBoost [15] and LightGBM [14], have shown strong performance in uplift tasks [12]; decision-tree-based uplift methods were systematically compared by Rzepakowski and Jaroszewicz [13]. Künzel et al. [30] introduced the X-learner meta-learner, which extends T-learner by imputing counterfactual outcomes in a two-stage procedure weighted by a propensity model — this design is particularly effective when treatment and control groups are imbalanced, a common condition in SME deployments where campaigns typically reach only a minority of the customer base. Existing literature focuses predominantly on e-commerce and subscription contexts. Application to POS-driven SME campaigns — with the additional constraint of per-customer margin validation — is a novel contribution of this work.

2.4 MLOps for SMEs

The MLOps literature has grown substantially around large-scale deployments, with Sculley et al. [16] identifying the hidden technical debt incurred when ML systems are embedded in production software, and Kreuzberger et al. [17] providing a formal definition and architecture taxonomy for MLOps. Paleyes et al. [18] survey real-world deployment challenges across a large body of case studies. Work specifically addressing MLOps design for SME constraints — limited compute, small datasets, absence of dedicated ML engineers — remains sparse. Model governance practices including Champion-Challenger selection are discussed in Shmueli et al. [19]. Fairness and bias considerations in ML systems — relevant to equitable campaign targeting across customer segments — are addressed in Barocas et al. [20]. Our Champion-Challenger protocol extends governance practice with a financially motivated update gate that promotes a challenger model only when it demonstrates measurable profit improvement over the incumbent champion.

2.5 LLM Integration in Business Pipelines

Large language model capabilities and limitations are surveyed in Zhao et al. [22], while hallucination risks in generative systems are systematically catalogued by Ji et al. [23] — motivating our structured post-generation validation step. We adopt a local, quantized LLM (llama3.2:3b via Ollama) [21] to ensure that no customer transaction data leaves the operator’s infrastructure, addressing data privacy concerns relevant to SME deployments. The local inference approach trades generation quality for zero ongoing inference cost and full data sovereignty — a trade-off appropriate for SME contexts.

2.6 SME Technology Adoption

Barriers to technology adoption among SMEs are well documented. Nguyen et al. [25] confirm that perceived complexity and resource constraints are the primary inhibitors of IT adoption in small businesses, consistent with the access gap in marketing analytics that this work addresses. CRM adoption patterns in SME contexts are examined by Harrigan et al. [24], who find that relationship management tools are most effective when they reduce rather than increase operational complexity — a design principle reflected in the plain-language LLM output layer of this framework.

4. Methodology

4.1 Layer 1 — RFM Customer Segmentation

Input: Raw POS transactions Output: Per-customer RFM decile (1–10) and K-means cluster assignment

We compute three metrics per customer from raw transaction history:

  • Recency (R): Days elapsed since the customer’s most recent transaction, relative to the analysis date
  • Frequency (F): Total count of distinct transactions
  • Monetary (M): Cumulative spend across all transactions

Outlier filtering: Prior to clustering, we apply Tukey-style outlier filtering on Monetary values. Records with Monetary > Q3 + 3 × IQR are excluded [6], where Q3 is the 75th percentile and IQR = Q3 − Q1. This prevents bulk buyers — common in SME data — from distorting segment centroids.

Normalization: All three dimensions are standardized to zero mean and unit variance (StandardScaler) to prevent Monetary (typically in hundreds) from dominating Recency and Frequency (typically single digits).

Dynamic cluster selection: Cluster count k is selected from k ∈ {2, …, 10} (minimum k=3 when n ≥ 300) by maximizing the silhouette score:

s(i)=b(i)−a(i)max⁡(a(i),b(i))s(i) = \frac{b(i) - a(i)}{\max(a(i), b(i))}

where a(i) is the mean intra-cluster distance and b(i) is the mean nearest-cluster distance for point i. The silhouette score ranges from −1 to +1, with higher values indicating better-defined clusters. The upper bound of k=10 matches the IBM 10-segment standard, allowing the clustering to fully resolve the customer distribution when data supports finer segmentation.

IBM 10-segment naming via rank-percentile normalization: Each cluster centroid is scored by normalizing its R, F, M values against the distribution of other cluster centroids (rank-percentile normalization) rather than against the global data maximum. For each dimension d∈{R,F,M}d \in \{R, F, M\}:

d̃k=percentile rank of dk among all {d1,…,dK}\tilde{d}_k = \text{percentile rank of } d_k \text{ among all } \{d_1, \ldots, d_K\}

A cluster with R̃k≥0.6\tilde{R}_k \geq 0.6 (low recency = recent) is classified as “high-R”; one with R̃k<0.4\tilde{R}_k < 0.4 as “low-R”. The same logic applies to F and M. The resulting (R-level, F-level, M-level) triple maps deterministically to one of ten IBM standard segment names: Champions, Loyal Customers, Potential Loyalist, Promising, Need Attention, About to Sleep, At-Risk, Can’t Lose Them, Hibernating, Lost. Rank-percentile normalization is essential: max-based normalization collapses all non-Champion clusters toward mid-range when a single Champion cluster has extreme F/M values, causing multiple clusters to receive the same name. Rank-percentile normalization compares clusters against each other, guaranteeing meaningful distribution of names across the full IBM taxonomy.

Rule-based segment flags: Four deterministic flags are applied after K-means to guarantee critical customer states are always represented, regardless of cluster geometry. Applied in priority order (highest first):

Flag Conditions Priority
Can’t Lose Them recency > 90d AND frequency ≥ 5 AND rfm_decile ≥ 7 1 (highest)
Churn Risk recency > 45d AND frequency ≥ 3 2
About to Sleep 25d < recency ≤ 45d AND frequency ≤ 4 3
New Customer recency ≤ 30d AND frequency ≤ 2 4

These flags ensure that a small restaurant dataset where K-means finds only 2 clusters still correctly identifies a drifting VIP (Can’t Lose Them) and a first-time visitor (New Customer) for tier-appropriate campaign actions.

Frequency trend: A behavioral velocity feature is computed for each customer by splitting their transaction history at the temporal midpoint and comparing visit counts in each half:

freq_trendi=visit_countrecent half−visit_countearly half\text{freq\_trend}_i = \text{visit\_count}_{\text{recent half}} - \text{visit\_count}_{\text{early half}}

Positive freq_trend indicates an accelerating customer; negative indicates a decelerating one. This feature feeds into adaptive flag thresholds: for customers with freq_trend < 0, the Churn Risk recency threshold tightens by 30% (recency > 32d instead of 45d) and the About to Sleep window expands by 10 days (up to 55d), surfacing at-risk customers earlier than static thresholds would detect.

4.2 Layer 2 — Market Basket Analysis and Category Profiling

Input: Raw POS transactions Output: Top-3 association rules; per-customer category affinity vector

We apply the Apriori algorithm to find frequent product co-purchase patterns. Three metrics govern rule quality:

  • Support: Fraction of transactions containing both items — set at minimum 0.01 for SME-scale data
  • Confidence: Conditional probability P(B | A)
  • Lift: Ratio of observed co-purchase frequency to expected frequency under independence. Lift > 1 indicates positive association; higher lift indicates stronger bundle potential

Rules are ranked by lift and the top three are surfaced for bundle campaign assignment. In parallel, each customer’s spend is aggregated by product category to produce a ranked top_category and top_product affinity profile used by Layer 3.

A graceful fallback is implemented: if the input CSV lacks a category column — common in basic POS exports — product_name is used as a proxy category, ensuring compatibility with minimally structured data.

Large-dataset pre-filter: Before constructing the transaction-item matrix, only the top-150 most frequently occurring products are retained. This bounds the basket matrix to a manageable size on commodity hardware regardless of catalog breadth, and concentrates association rule mining on products with sufficient support to produce actionable recommendations.

4.3 Layer 3 — Context Detection and Campaign Matching

Input: Layer 1 cluster assignments, Layer 2 category profiles, timestamps Output: Per-transaction context flags; initial campaign assignment

Temporal context: Timestamps are localized to the business timezone (configurable; default Asia/Bangkok) before hour extraction. Peak hours are determined through data-driven analysis of transaction volume. For each hour h∈{0,1,…,23}h \in \{0, 1, \ldots, 23\}, the hourly transaction count nhn_h is computed from the full dataset. The peak threshold is:

peak_threshold=n‾+0.5×σn\text{peak\_threshold} = \bar{n} + 0.5 \times \sigma_n

where n‾\bar{n} is the mean hourly transaction count and σn\sigma_n is its standard deviation. Hours where nh>peak_thresholdn_h > \text{peak\_threshold} are designated peak; all others are off-peak. This approach automatically adapts to each dataset’s traffic distribution without manual configuration — a UK wholesale dataset peaks at 11:00–15:00, while a Thai F&B dataset peaks at 17:00–21:00, and both are detected without code changes. If the dataset lacks statistical spread (e.g., single-day test data), the algorithm falls back to configured defaults (default 17:00–21:00). Transactions occurring in peak hours are flagged Peak; all others Off-Peak. Off-peak promotions target demand stimulation during low-traffic periods, preserving full-margin sales during peak hours.

Inventory estimation: In the absence of live inventory feeds — standard in SME deployments — remaining stock is estimated from a velocity-based replenishment model:

initial_stock_est=total_quantity_soldT×R×buffer_multiplier\text{initial\_stock\_est} = \frac{\text{total\_quantity\_sold}}{T} \times R \times \text{buffer\_multiplier}

remaining_stock=initial_stock_est−recent_demandR\text{remaining\_stock} = \text{initial\_stock\_est} - \text{recent\_demand}_{R}

where T is the observation window in days, R is the assumed replenishment cycle (default 14 days), and recent_demand_R is quantity sold in the last R days. This formulation correctly identifies fast-moving products with accelerating recent demand — rather than low-volume products — as candidates for stock-out exclusion. Products with remaining_stock ≤ 5 units are flagged out-of-stock and excluded from bundle recommendations.

Campaign matching applies a rule engine combining cluster tier, category affinity, and context flags to produce an initial campaign assignment, subsequently refined by Layer 4’s uplift and margin analysis.

4.4 Layer 4 — Uplift Modeling and CFO Guardrail

Input: Enriched customer records from Layers 1–3; data-driven COGS and discount rate estimates Output: Per-customer uplift_score, recommended_action, expected_profit, should_send flag; broadcast_list.csv; champion/challenger model comparison report; enriched segment payload for Layer 5

4.4.0 Data-Driven Rate Estimation

Prior to uplift modeling, COGS rate and discount rate are estimated from transaction data when sufficient coverage exists:

COGS rate: The P10 (10th percentile) of unit price per product is treated as a proxy for cost floor (below which a sale would represent a loss). The data-driven COGS rate is:

ĉCOGS=mean(P10jp‾j) for all products j with nj≥5\hat{c}_{\text{COGS}} = \text{mean}\left(\frac{P10_j}{\bar{p}_j}\right) \text{ for all products } j \text{ with } n_j \geq 5

where P10jP10_j is the 10th percentile of unit_price for product jj and p‾j\bar{p}_j is its mean price. This is only activated when ≥10 distinct products satisfy the coverage threshold; otherwise the config default (0.50) is used.

Discount rate: Estimated from the observed frequency of discounted transactions:

d̂=fpromo×dconfig\hat{d} = f_{\text{promo}} \times d_{\text{config}}

where fpromof_{\text{promo}} is the fraction of rows with promo_type ∈ {coupon, discount} and dconfigd_{\text{config}} is the configured default discount rate. This anchors the estimate to the operator’s actual promotional activity rather than an assumed rate.

Both estimates are logged at runtime with their source label (data_driven or config_default), enabling full auditability.

4.4.1 Uplift Model (X-Learner)

The production pipeline implements an X-learner meta-learner [30] using LightGBM (n_estimators = 200), upgraded from an initial T-learner baseline (AUUC = 0.0612 on randomized labels; prior reported value of 0.2351 was inflated by proxy label bias — see Section 6.10.1) to better handle the imbalanced treatment/control group sizes typical of SME deployment. The X-learner trains five LightGBM models in three stages:

Stage 1 — Base outcome models (LGBMClassifier):

  • μ₁(x): P(Y=1 | T=1, X=x) — trained on treated customers (was_treated = 1)
  • μ₀(x): P(Y=1 | T=0, X=x) — trained on control customers (was_treated = 0)

Stage 2 — Imputed treatment effects:

Di1=Yi−μ̂0(Xi)for treated customersD^1_i = Y_i - \hat{\mu}_0(X_i) \quad \text{for treated customers} Di0=μ̂1(Xi)−Yifor control customersD^0_i = \hat{\mu}_1(X_i) - Y_i \quad \text{for control customers}

where Di1D^1_i is the observed outcome minus the estimated counterfactual (what the treated customer would have done without the campaign), and Di0D^0_i is the reverse imputation for control customers.

Stage 3 — CATE estimators (LGBMRegressor):

  • τ₁(x): E[D¹ | X=x] — trained on treated customers, targeting imputed treatment effect
  • τ₀(x): E[D⁰ | X=x] — trained on control customers, targeting imputed treatment effect

Propensity weighting (LGBMClassifier):

A fifth model estimates the propensity score e(x) = P(T=1 | X=x), trained on all customers. The final per-customer CATE estimate is:

τ̂(x)=e(x)⋅τ̂0(x)+(1−e(x))⋅τ̂1(x)\hat{\tau}(x) = e(x) \cdot \hat{\tau}_0(x) + (1 - e(x)) \cdot \hat{\tau}_1(x)

This formulation weights the two CATE estimators by treatment probability: in the common SME case where few customers are treated (low e(x)), the control-side estimator τ₀(x) dominates, which is better estimated from the larger control group. This corrects the T-learner’s primary weakness — when treatment/control groups are imbalanced, the T-learner’s direct difference μ̂1−μ̂0\hat{\mu}_1 - \hat{\mu}_0 is dominated by the less-precise model trained on the smaller group.

Backward compatibility: A TLearnerModel wrapper preserves compatibility with previously saved Champion models trained under the T-learner architecture. Loaded legacy models expose the same predict_uplift() interface as XLearnerModel, enabling Champion-Challenger comparisons across architecture generations.

Fallback: If either treatment or control group contains fewer than 10 customers, the pipeline falls back to T-learner training to prevent degenerate Stage 2 imputation.

Positive uplift indicates incremental expected purchase attributable to the campaign. Negative uplift indicates the customer would likely purchase regardless, making campaign spend wasteful.

Important caveat: X-learner uplift is only causally interpretable when treatment assignment is randomized. In the absence of a randomized experiment — typical at first SME deployment — the model produces a response-propensity heuristic, not a causal estimate. The 5% ongoing holdout control group enables properly randomized uplift measurement to accumulate over time, converting the system from a batch propensity scorer into a growing randomized experiment.

Label sourcing — real vs. proxy: The pipeline supports two label modes selected automatically at runtime:

  1. Real promotion response mode (preferred): When is_treated and post_promo_visit columns are present in the POS file, the system uses these as treatment and conversion labels. When a marketing_campaign.csv file is additionally present with AcceptedCmp1–AcceptedCmp5 and Response columns, three additional behavioral features are activated: income, total_spend, and times_accepted. Note that AcceptedCmp columns record whether a customer accepted a campaign offer — they are observational outcomes, not randomized treatment assignments. Uplift estimates from this source reflect self-selection bias and should be interpreted as directional signals rather than causal effects.

  2. Temporal-split proxy mode (fallback): When no promotion response file is available — the common case for first-time SME deployments — the system constructs proxy labels from transaction timestamps rather than RFM rank. The observation window is split at the 75th percentile date: converted = 1 if the customer transacted in the final 25% of the window (a temporal retention signal independent of RFM rank); was_treated is assigned by seeded random assignment (~40% treated). This design was adopted following an identified defect in an earlier RFM-based proxy (was_treated = rfm_decile ≥ median, converted = frequency > 1), where both label sources overlapped with model features rfm_decile_segment and frequency, producing circular training: the model learned to rank customers by RFM score rather than discover uplift signal. The temporal-split proxy eliminates this circularity: label construction uses only transaction dates, and model features are restricted to basket-level signals (total_price, quantity, is_campaign_spike) that do not participate in label derivation. Under random treatment assignment, the expected AUUC is approximately zero — the correct outcome when no causal treatment effect can be estimated without a real experiment. This conservative behaviour is intentional: the system should not manufacture uplift signal from observational data.

Feature Proxy Mode Real Label Mode

A 5% holdout control group is preserved in every deployment cycle for ongoing A/B measurement of realized incremental lift. As real promotion response data accumulates through partner deployments, operators automatically transition from proxy mode to real label mode without pipeline reconfiguration.

Probability calibration: Raw LightGBM predict_proba() output is known to produce uncalibrated scores — a predicted probability of 0.7 does not reliably correspond to a 70% observed event rate [35]. In the CFO Guardrail profit formula:

incremental=gross_margin×(ptreated−pbaseline)−promo_cost\text{incremental} = \text{gross\_margin} \times (p_{\text{treated}} - p_{\text{baseline}}) - \text{promo\_cost}

uncalibrated pbaselinep_{\text{baseline}} and ptreatedp_{\text{treated}} propagate directly into profit estimates. To address this, the base learners μ₀ and μ₁ are wrapped with CalibratedClassifierCV(method='isotonic', cv=3), which fits an isotonic regression calibrator on out-of-fold predictions. Benchmarked Expected Calibration Error (ECE) on a held-out test set improved from 0.2496 to 0.0323 — an 87% reduction — confirming that calibrated probabilities reliably reflect the actual conversion base rate. The propensity model already applied isotonic calibration independently. The T-learner fallback (n < 50 per group) is left uncalibrated: with fewer than 50 samples, a three-fold cross-validation calibrator would be fit on fewer than 17 samples per fold, introducing more variance than it removes.

4.4.2 Dunnhumby Real-Data Training

The Dunnhumby Complete Journey dataset was selected as the primary source for real-data uplift training because it is the only dataset in this evaluation with a genuine, naturally occurring treatment/control split. Of the 2,500 households in the dataset, 1,584 appear in campaign_table (treated) and 916 never received any campaign mailer across the full 711-day study window (control). This natural holdout structure enables a causal framing absent from the other datasets.

Why Dunnhumby and not marketing_campaign.csv: The marketing_campaign.csv dataset (Dataset 2) contains no treatment/control split — Z_CostContact = 3 for every row, indicating all 2,240 households were contacted in each campaign. Response records offer acceptance, not a contacted/not-contacted flag. Without a control arm, it is not possible to estimate individual treatment effects, and this dataset cannot be used for uplift training without an external holdout.

Feature engineering: Nine pre-campaign behavioral features are computed from transaction history with a hard temporal cutoff at the day before each campaign’s START_DAY, preventing any information leakage from the campaign period:

Outcome definition: The binary purchase indicator Y = 1 if the household made at least one purchase during the [START_DAY, END_DAY] campaign window, as specified in campaign_desc.csv. Selection bias disclosure: Treated households exhibit substantially higher pre-campaign spend than control households (treated mean: $2,032; control mean: $433; ratio ≈ 4.7×). This strong positive selection — high-value shoppers were preferentially targeted — means a naive uplift model will conflate “likely to buy regardless” with “responds to promotion.” To correct for this, the propensity score e(x) = P(T=1 | X=x) is estimated from the same nine features, clipped to [0.1, 0.9] to prevent extreme inverse-probability weights, and the doubly-robust AUUC (DR-AUUC) is used as the primary evaluation metric in place of standard AUUC. DR-AUUC combines the direct model estimate with an inverse-propensity-weighted correction, providing consistent estimates of the causal ranking even under non-random treatment assignment [31].

Expected performance range: Under proper doubly-robust evaluation, target AUUC is 0.60–0.68. Values above 0.70 without propensity correction likely indicate selection bias leakage — the model is ranking high-value shoppers rather than genuinely persuadable ones. The retrain run applying this methodology is currently pending (see Section 6.6 cross-dataset comparison).

4.4.4 2-Step Decision Engine

The Layer 4 decision process is restructured as a two-step pipeline: Step 1 handles hard stops and uplift-group classification; Step 2 selects the best profitable action from a declarative rule library per customer’s classified group and context. This separation makes financial logic explicit and auditable, and replaces a monolithic if/elif cascade with composable components.

Step 1 — Hard Stops and Uplift Group Classification

AOV thresholds are applied adaptively: if the dataset median avg_spent falls below the configured low_basket_threshold, thresholds are replaced by the P10 and P50 of actual avg_spent to prevent universal Do Nothing on low-AOV datasets.

4.4.5 Declarative Action Rule Engine

Step 2 of the decision engine selects the best profitable campaign action from a declarative rule library defined in action_rules.py. Rules are organized into two pools evaluated under different strategies:

  • SURE_THING_RULES (5 rules): Evaluated in declaration order; the first rule that is profitable under the loyalty viability check (_viable_loyalty) wins. Loyalty-only actions — VIP points, early access, welcome offers — are permitted; percentage discounts are excluded, as sure-thing customers convert regardless and do not require discount incentive.

  • PERSUADABLE_RULES (38 rules): All rules whose tier, time_context, rfm_min, and uplift_min conditions match the customer are evaluated; all profitable rules are collected; the action with the highest expected profit wins.

Each rule is a data record with the following schema:

Field Type Description

This declarative structure separates what qualifies a customer from how profitability is calculated, enabling new campaigns to be added by inserting a rule record without modifying any scoring logic. The 38 persuadable rules cover all 10 IBM tiers — Loyal Customers, Potential Loyalist, Promising, Need Attention, About to Sleep, New Customer, Churn Risk, Can’t Lose Them, Champions, At-Risk, Hibernating, and Mid — each with 2–5 rules spanning peak/off-peak contexts and RFM eligibility.

Rescue mode and viability functions: Two viability functions govern the profit check applied within each rule:

_viable(r)={Trueif net_margin≥floor∧Δprofit>0Falseotherwise\text{\_viable}(r) = \begin{cases} \text{True} & \text{if net\_margin} \geq \text{floor} \;\wedge\; \Delta\text{profit} > 0 \\ \text{False} & \text{otherwise} \end{cases}

where Δprofit=gross_margin×(ptreated−pbaseline)−promo_cost\Delta\text{profit} = \text{gross\_margin} \times (p_{\text{treated}} - p_{\text{baseline}}) - \text{promo\_cost} is the incremental profit above baseline. The standard _viable check requires both margin compliance and positive incremental return; _viable_loyalty only requires that the promo cost does not eliminate baseline profit. For rescue-mode customers (churn_risk / cant_lose / hibernating / about_to_sleep), _viable_loyalty is used: the economic rationale is that retaining a high-value customer has long-term value exceeding the incremental transaction profit, and requiring strict incremental proof before dispatching a retention message would suppress appropriate investment.

4.4.6 CFO Guardrail

Before finalizing any campaign assignment, two per-customer financial checks are applied:

1. Net margin floor check (per campaign type):

gross_revenuei=AOVi×(1−d)\text{gross\_revenue}_i = \text{AOV}_i \times (1 - d)

net_profiti=gross_revenuei−AOVi×cCOGS−AOVi×rpromo\text{net\_profit}_i = \text{gross\_revenue}_i - \text{AOV}_i \times c_{\text{COGS}} - \text{AOV}_i \times r_{\text{promo}}

net_margini=net_profitigross_revenuei\text{net\_margin}_i = \frac{\text{net\_profit}_i}{\text{gross\_revenue}_i}

where dd is the campaign discount rate and rpromor_{\text{promo}} is the promo cost rate (both specific to the assigned action type). If net_margin_i < min_allowable_net_margin (default 0.15), the action is overridden to Do Nothing.

2. Per-customer incremental profit check:

Δprofiti=[gross_margini×P̂(convert∣treated)i−promo_costi]−[gross_margini×P̂(convert∣control)i]\Delta\text{profit}_i = [\text{gross\_margin}_i \times \hat{P}(\text{convert} \mid \text{treated})_i - \text{promo\_cost}_i] - [\text{gross\_margin}_i \times \hat{P}(\text{convert} \mid \text{control})_i]

If Δprofiti≤0\Delta\text{profit}_i \leq 0, the campaign is expected to cost more than the incremental revenue it generates for customer i, and the action is overridden to Do Nothing. This check is genuinely per-customer because Δprofiti\Delta\text{profit}_i depends on each customer’s predicted uplift score and individual AOV.

Both checks must pass for a campaign action to be dispatched. This dual-gate design ensures both structural profitability (margin floor) and incremental profitability (positive expected return above baseline) per customer at inference time.

Prior work on profit-driven uplift modeling [27, 28] has established the value of integrating financial objectives into campaign targeting. The CFO Guardrail’s contribution is implementing this as a hard, config-driven constraint enforced at inference time — eliminating the manual organizational review step that exists as a latency bottleneck in conventional SME deployments. The dual viability check integrates with the rescue tier mechanism (Section 4.4.5) through two distinct functions: _viable enforces both margin floor and incremental profit requirement for standard persuadable customers; _viable_loyalty relaxes the incremental requirement to baseline-profit preservation for rescue-tier customers where retention economics justify the investment.

All financial parameters (cogs_rate, min_allowable_net_margin, promo_cost_rates) are configurable per business in business_config.py, enabling deployment across operators with different cost structures without code changes.

4.4.6b Broadcast List and Layer 4 → Layer 5 Integration

Layer 4 produces two outputs consumed downstream:

  1. broadcast_list.csv — one row per customer with should_send = 1, containing: customer_id, segment_name, recommended_action, offer, expected_profit, send_date, channel. This file is the direct automation payload for CRM tools (Mailchimp, LINE OA, SMS gateway) and contains only CFO-approved customers.

  2. Enriched segment payload (merge_layer4_into_payload) — per-segment aggregation of Layer 4 decisions merged back into the campaign plan before passing to Layer 5. Each segment is augmented with:

    • suppressed_count: number blocked by any guardrail or “Do Nothing” rule

This integration ensures that the Layer 5 executive report reflects only financially approved campaign activity, not the full segment population.

Champion feature-count guard: When loading a saved Champion model for comparison, the pipeline checks that the Champion’s feature count matches the current dataset’s feature set. If they differ — indicating the Champion was trained on a different dataset or label mode — the comparison is skipped and the Challenger is promoted as the first Champion for this context, with a logged warning.

4.4.7 Champion-Challenger Protocol

Model versioning follows a Champion-Challenger pattern. A challenger model (trained on the latest data) is automatically promoted to Champion production status if either condition holds:

  • Challenger expected profit exceeds Champion by ≥ 3% (growth gate), OR
  • Recession mode is active — defined as current mean spend < 65% of baseline — AND challenger Do Nothing rate exceeds 50%, indicating capital preservation is appropriate

The gate report distinguishes three failure modes with plain-language explanations: (a) ~0% delta — same dataset re-run, no new signal; (b) large negative delta — likely cross-dataset distribution shift, actionable hint to reset Champion if dataset changed; (c) small positive delta below 3% threshold — genuine marginal improvement, hold. Each run prints a full action breakdown (✓/✗ per decision type with counts and percentages) for operational transparency.

Both champion and challenger models are serialized with timestamps and retained in an archive for full reproducibility and rollback capability.

4.4.8 Budget-Constrained Campaign Targeting

Layer 4 produces a list of CFO-approved customers with per-customer expected_profit and promo_cost. When the operator specifies a campaign spend ceiling, budget_optimizer.py selects the profit-maximizing subset within that ceiling.

Algorithm: Greedy bang-per-buck ordering. For each CFO-approved customer compute:

bang_per_bucki=expected_profitimax⁡(promo_costi,0.01)\text{bang\_per\_buck}_i = \frac{\text{expected\_profit}_i}{\max(\text{promo\_cost}_i, 0.01)}

Sort descending and select greedily until cumulative_cost > budget. Greedy bang-per-buck is provably optimal for the fractional knapsack. For the 0/1 knapsack, the algorithm achieves at least a 1/2-approximation when combined with the option of selecting the single highest-profit customer as an alternative: max(greedy result, best single item) ≥ ½ × OPT. At realistic SME customer-list sizes (hundreds to low thousands), the approximation gap is small and the O(n log n) runtime is negligible.

Customers excluded by the budget ceiling receive should_send = 0 with recommended_action = "Do Nothing (Over Budget)" — distinguishable from CFO-guardrail suppression in reporting. When budget ≤ 0 or budget = None, all CFO-approved customers are selected unchanged, preserving backward compatibility with pre-budget deployments.

Diminishing marginal ROI: As the budget ceiling is relaxed, the optimizer admits progressively lower-bang-per-buck customers. This produces a characteristic diminishing-returns pattern where each incremental ฿/$ of budget yields decreasing expected profit — a natural consequence of the fixed population and fixed per-customer profit values.

4.4.9 CLV-Informed Rescue Tier Viability

The two viability functions introduced in Section 4.4.4 (_viable and _viable_loyalty) rest on two distinct financial logics. The _viable_clv() function introduced here adds a third logic specifically for rescue-tier customers: a campaign investment is justified when the promotion cost does not exceed the revenue at risk from customer churn.

BG/NBD survival model: clv_model.py fits a Beta-Geometric / Negative Binomial Distribution (BG/NBD) model (Fader et al. 2005 [34]) to the raw transaction history at serving time, producing per-customer estimates:

  • P(alive) — probability that the customer has not yet churned, given their purchase history
  • expected_txns — expected number of transactions in the next 90 days (configurable via clv_horizon_days)
  • clv_estimate = gross_margin_rate × avg_spend × expected_txns
  • clv_at_risk = clv_estimate × (1 − P(alive)) — the expected revenue lost if this customer churns without intervention

**_viable_clv logic:**

if clv_at_risk <= 0:
    return _viable_loyalty(rate_key)   # fallback: no CLV data
promo_cost = avg_spent * PROMO_COST_RATES[rate_key]
profit     = gross_margin * p_baseline - promo_cost
return (promo_cost <= clv_at_risk AND profit > 0), profit, promo_cost

The dual condition — promotion cost must not exceed CLV at risk and baseline profit must remain positive — prevents approval of campaigns that are justified by retention value alone but are operationally unprofitable on the transaction.

Fallback design: BG/NBD requires a low-to-medium purchase frequency distribution and a sufficient number of repeat purchasers (≥ 20) to fit reliably. For high-frequency retail datasets (daily/weekly purchases, e.g., a bakery), the BG/NBD optimizer may fail to converge — a known limitation documented in the survival modeling literature. When clv_at_risk = 0 (convergence failure or insufficient data), _viable_clv delegates to _viable_loyalty, preserving the existing heuristic behavior without requiring manual configuration.

4.4.10 Pooled Multi-Treatment Uplift

Standard single-treatment uplift models produce one CATE score per customer — the estimated incremental effect of sending any campaign. When multiple distinct offer types are available (discount, points, bundle, reactivation), one-vs-rest training fits a separate model per arm, requiring N × data and N × training time while preventing cross-arm signal sharing.

Pooled learning design: PooledMultiTreatmentModel trains a single X-learner where the treatment arm is encoded as one-hot features:

Row type arm_mens_email arm_womens_email was_treated
Control (no email) 0 0 0
Treated — mens email 1 0 1
Treated — womens email 0 1 1

The tau (CATE) models learn: “given customer characteristics X and arm indicator A, what is the conditional average treatment effect?” This shared parameterization allows the model to transfer signal from men’s-email responders to women’s-email prediction and vice versa, reducing variance for arms with fewer observations.

Inference: predict_all_cates(X) queries the single base model once per arm, setting the arm features to that arm’s indicator vector. predict_best_treatment(X) returns the arm with the highest predicted CATE per customer. predict_uplift(X) returns the best CATE for compatibility with the existing single-treatment serving pipeline. feature_names_ stores only the base features (excluding arm columns) — the serving pipeline passes base features; arm columns are added internally.

Base features (18): recency, history_log (log₁ of purchase history), mens, womens, newbie, zip_rural, zip_suburban, zip_urban, channel_multichannel, channel_phone, channel_web, hist_seg_1 through hist_seg_7 (seven history-segment one-hot indicators).

4.6 Layer 6 — Campaign Automation and Monthly Scheduling

Input: Broadcast list with recommended actions, segment-level send windows, and historical customer metadata Output: Three time-distributed artifacts for downstream campaign execution

The campaign scheduler operationalises broadcast decisions by translating broadcast_list.csv into a time-distributed monthly campaign schedule spanning all four calendar weeks. This distribution strategy mitigates notification fatigue — a known contributor to reduced click-through rates and unsubscribe risk in retention marketing — by spreading sends across distinct temporal windows rather than concentrating them on a single batch date.

Three wavefronts are deployed based on action type and promotional intent. Wave 1 (Off-Peak Traffic Driver) targets customers whose majority transaction context is Off-Peak, with notification sent one hour before the off-peak window opens; the early notification acts as a demand catalyst to pull engagement into otherwise quiet periods. Waves 1 deploys in weeks 1 and 3 to allow off-peak segments a mid-month re-engagement opportunity. Wave 2 (Peak Upsell) executes during established high-traffic hours, with notification one hour before the peak window opens, positioning the message as a reminder to customers already predisposed to visit. Wave 2 deploys in weeks 2 and 4. Wave 3 (VIP Early Access) grants exclusive early-window access reserved to week 1, reinforcing VIP status perception through temporal exclusivity.

Per-customer send_datetime is derived from the customer’s detected send_window (Peak or Off-Peak) and hashed customer ID, ensuring consistent assignment across re-runs while distributing sends evenly across the available send days within each wave’s allocated weeks.

The 5% holdout mechanism withholds a random control cohort from all campaign sends, selected by seeded random sampling for reproducibility. This true holdout group enables causal lift measurement via post-campaign transaction comparison without requiring a concurrent unpromoted segment — providing the causal ground truth needed to validate model-estimated incremental profit figures against realised revenue.

Message templates are pre-rendered per action type and truncated to channel-specific character limits (SMS ≤160 characters; LINE ≤500; Email ≤2,000), incorporating offer descriptors, temporal urgency markers, and action-specific calls to action. Three output artefacts are generated: campaign_schedule_YYYY-MM.csv (customer-level send datetime, channel, message, expected profit), ab_holdout_YYYY-MM.csv (control cohort metadata), and campaign_summary_YYYY-MM.json (daily send cadence, wave distribution, projected profit aggregates). These artefacts feed directly into CRM and campaign execution platforms.

Post-campaign feedback loop: A companion holdout_evaluator.py module closes the measurement loop by ingesting actual purchase outcomes after the campaign window closes. The operator provides actual_outcomes_YYYY-MM.csv (minimum columns: customer_id, purchased) exported from the POS system, and the evaluator joins it against the treatment and control groups to compute: (1) treatment vs. control conversion rates with 95% Wilson score confidence intervals; (2) absolute and relative incremental lift; (3) two-proportion z-test for statistical significance (with scipy fallback to normal approximation); (4) incremental revenue per customer vs. model-predicted profit per customer — a direct model accuracy diagnostic. The evaluator exports outcomes_labeled_YYYY-MM.csv containing is_treated and post_promo_visit columns derived from observed outcomes. This file is structurally compatible with Layer 4’s real label mode: passing it as promo_response_path in the next pipeline cycle causes the uplift model to retrain on causally identified outcomes rather than proxy labels, completing the reinforcement loop from deployment → observation → retraining.

5. Experiments

5.1 Datasets

Seven datasets were used to evaluate the framework across complementary dimensions: synthetic F&B for methodology validation; a public marketing campaign dataset; a large-scale real-world grocery dataset; a UK e-commerce dataset; a purpose-built Layer 3 synthetic test; the Hillstrom MineThatData RCT for multi-treatment uplift evaluation on true randomized labels; and a production dessert restaurant POS dataset supplying the Champion v7 production model.

Dataset 1 — Synthetic Restaurant POS Dataset

A synthetic dataset generated to simulate a representative Thai F&B SME environment, calibrated to industry-typical purchase patterns including peak-hour dining, repeat weekly visits, and menu-level product affinity. The dataset contains 9,344 transaction line items (each line item is a single menu item ordered in a visit; a single customer visit may produce multiple line items) from 200 unique customers across a 6-month observation window (May–November 2026). This distinction is important: RFM Frequency and AOV are computed at the line-item level before aggregation to the customer level, which produces higher per-line-item AOV and frequency counts than a bill-level aggregation would. Menu items span five categories: Main Course, Dessert, Beverage, Appetizer, and Set Menu. Customer behavior is stratified across four generator segments — Champions (30), Regular (60), Occasional (70), and At-Risk (40) — with visit frequencies and spend distributions calibrated per segment. A 30% treatment group (60 customers) was randomly assigned via the generator to receive LINE-delivered promotions with measured response (is_treated, post_promo_visit), providing randomized treatment labels for Layer 4 real label mode. The treatment assignment is randomized at the generator level, making this dataset suitable for T-learner uplift evaluation on a simulated randomized experiment. This dataset directly represents the target SME deployment context.

Dataset 2 — Marketing Campaign Dataset

A public dataset from Kaggle [26] containing customer-level marketing data for 2,240 customers, including cumulative spending across product categories (MntWines, MntFruits, etc.), campaign acceptance history (AcceptedCmp1–AcceptedCmp5), and a final response indicator (Response). Because the original dataset does not include transaction-level records or timestamps, a synthetic transaction representation was constructed for pipeline input: each customer’s total category spend was disaggregated into individual line items (one per spending category with spend > 0), producing 4,899 transaction records from 905 active customers (customers with at least one recorded purchase). Timestamps for Layer 3 context detection are synthetically generated and carry no real-world temporal meaning for this dataset; Layer 3 context results from this dataset are informational only. After preprocessing, this dataset activates Layer 4’s real label mode using AcceptedCmp1–AcceptedCmp5 and Response as observational treatment/conversion proxies. All values are in USD (not THB). Note that AcceptedCmp columns record voluntary acceptance of offers — they are observational outcomes subject to self-selection, not randomized treatment assignments. Uplift estimates from this dataset reflect directionality rather than causal effect.

Dataset 3 — Dunnhumby Complete Journey (Grocery Retail)

The Dunnhumby Complete Journey dataset [29] is a public real-world grocery loyalty dataset covering 2,500 households across a 117-week observation window. The raw data comprises five files joined at preprocessing time: transaction_data (individual line items with household_key, BASKET_ID, PRODUCT_ID, SALES_VALUE, QUANTITY, discount fields), product (product names from COMMODITY_DESC and SUB_COMMODITY_DESC), campaign_table (which households received which campaigns), and coupon_redempt (coupon redemption events). Timestamps are reconstructed from the DAY integer field (anchored to 2024-01-01) and TRANS_TIME (HHMM integer), yielding real transaction-level timestamps for Layer 3 context detection. After joining, the combined dataset contains 2,576,815 transaction rows from 2,500 unique customers.

Treatment labels are derived from campaign_table membership (is_treated = 1 if the household received any campaign). Conversion proxy (post_promo_visit) is defined as purchasing in the latter half of the study period (week number above the dataset median), which provides a week-independent conversion signal applicable to both treated and control households. Promo type (coupon / discount / none) is inferred from COUPON_DISC, COUPON_MATCH_DISC, and RETAIL_DISC fields. This dataset is used with Layer 4’s real label mode in combination with an auxiliary marketing_campaign.csv file for behavioral features (income, total_spend, times_accepted). The dataset spans US grocery retail; all values are in USD. This is the largest and most computationally demanding dataset evaluated, exercising the top-150 product filter, adaptive basket thresholds, and data-driven rate estimation.

Dataset 4 — UK Online Retail Dataset

A public real-world e-commerce dataset containing transaction records from a UK-based online retailer. The dataset contains 397,884 transaction line items from 4,338 unique customers. Product names are catalog item identifiers (e.g., decorative goods and gift items); all values are in USD. Unlike the grocery datasets, product prices in this catalog are largely fixed (no unit_price variance across transactions for most products), making the data-driven P10/mean COGS estimation inapplicable — the pipeline falls back to the config default (COGS = 50%, discount = 15%). Market basket analysis found no association rules meeting the minimum support/confidence thresholds, reflecting the heterogeneous and low-repeat-purchase nature of specialty e-commerce catalogs. Adaptive basket thresholds activate (P10 = $5.99, P50 = $17.72), consistent with the moderate AOV of the mid-tier segment. This dataset exercises the pipeline’s graceful fallback behavior under both config-default rate estimation and absent MBA bundles.

Dataset 5 — Synthetic Layer 3 Context Detection Test

A purpose-built synthetic dataset designed to produce the temporal demand variation and stock-depletion conditions required to exercise Layer 3 in a controlled, verifiable manner — conditions absent from all four public datasets evaluated. The dataset contains 6,004 transaction rows from 500 unique customers across a 90-day observation window (2025-08-01 to 2025-10-29), with two engineered signal types:

Peak-hour clustering: 70% of transactions are sampled from the 17:00–21:00 window (CONFIG peak_hour_start/peak_hour_end), with the remaining 30% distributed uniformly across off-peak hours. This creates a verifiable peak/off-peak classification rate that Layer 3 should reproduce.

Demand surge stockouts: 10 products are included — 7 stable products with uniform daily demand throughout the 90 days, and 3 “hot” products (Special Edition Gift Set, Holiday Hamper Box, Premium Scented Candle Bundle) that receive a 6× demand surge in the final 14 days relative to their pre-surge baseline. Under the Layer 3 velocity-based stock estimation formula (initial_stock_est = daily_rate × 14 × 1.5; remaining_stock = initial_stock_est − recent_demand₁₄), this surge causes recent_demand to exceed initial_stock_est × 0.80 for all three products — triggering in_stock = False. The 7 stable products remain below the depletion threshold and stay in_stock = True.

Treatment/conversion labels are generated with realistic treatment rate (39.2% of 500 customers, i.e., 196 customers treated; this is a customer-level treatment rate, not a row-level rate) and a directional uplift signal (treated conversion 56.1% vs control 38.5%) suitable for X-learner training on temporal-split proxy mode (no separate promo response file; same-file detection path). This dataset is used exclusively for Layer 3 and Layer 4 Out-of-Stock validation — it is not used to report AUUC or financial projections.

A real-world production POS dataset from a Thai dessert restaurant (referred to as dessert-ml.csv), containing transaction-level records from 2,409 unique customers across 27,767 transaction rows, spanning November 2025 to September 2026 (~11 months, single store). Unlike Dataset 1 (synthetically generated for methodology validation), this dataset represents genuine SME POS exports — the pipeline’s direct target deployment context.

The dataset includes real treatment labels (is_treated, post_promo_visit) from actual promotional campaigns, with 1,702 treated customers (70.7%) and 707 control customers (29.3%). The high treatment rate is a characteristic of first-deployment SME contexts where operators have historically sent promotions broadly. Its role is to supply the production POS context for send-rate and financial reporting. The Champion v7 model trained on the combined pool achieves Qini = 1.21 and a +3.56% gate improvement over the previous champion, with a send rate of 50.1% (up from 8.9% on the prior architecture).

6.7 Champion-Challenger Performance

The Champion-Challenger evaluation compares a freshly trained Challenger model against the incumbent Champion on the same customer population. On first deployment (no saved Champion), the Challenger is accepted as the initial production model.

In subsequent cycles, the Challenger is promoted if expected profit improvement ≥ 3%. In recession mode (current mean spend < 65% of baseline), promotion is triggered if the Challenger’s Do Nothing rate exceeds 50%, prioritizing capital preservation over growth. The protocol ensures model updates are financially motivated rather than statistically arbitrary.

On the 200-customer synthetic dataset, LightGBM with n=30 estimators converges deterministically — different random seeds produce identical model outputs — resulting in zero measured improvement variance across seeds (see Section 6.10.5). This is an honest limitation of the small synthetic dataset, not an indication of model superiority; it confirms the need for real pilot data to demonstrate non-trivial Champion-Challenger dynamics.

6.10.2 Profit-Weighted Qini and Optimal Targeting Fraction

While AUUC measures the rank quality of an uplift model — whether higher-scored customers genuinely have higher incremental response — it does not directly quantify business value. A model with near-zero AUUC on null data correctly abstains from targeting; a model on real campaign data may produce strong AUUC yet still destroy value if promo costs exceed the incremental margin generated. The profit-weighted Qini bridges this gap by translating uplift scores into expected profit at every targeting depth.

Definition. Customers are sorted by predicted uplift score in descending order. At each rank position k, cumulative expected margin contribution (before promo cost) is:

Π(k)=∑i=1kavg_spenti×(1−COGS)×τ̂i\Pi(k) = \sum_{i=1}^{k} \text{avg\_spent}_i \times (1 - \text{COGS}) \times \hat{\tau}_i

where τ̂i\hat{\tau}_i is the X-learner uplift score for customer i and COGS = 0.50. This quantity measures the incremental gross margin the model expects from targeting the top-k customers — it does not subtract promotional cost (which is accounted for separately by the CFO Guardrail at dispatch time). The curve’s shape identifies which fraction of customers provides positive expected return on the margin side. The optimal targeting fraction is the point where the marginal contribution of adding one more customer turns negative — in practice, the point where the next customer’s τ̂i\hat{\tau}_i falls below zero.

The profit-weighted Qini is distinct from the CFO Guardrail’s Δprofit check: the Guardrail applies avg_spent × (1-COGS) × τ̂ − promo_cost > 0 per customer and blocks those where promo cost exceeds incremental margin. The Qini curve above measures cumulative margin contribution only, providing a rank-quality diagnostic independent of the specific promo cost rate.

Dataset 1 — Synthetic Restaurant (200 customers, X-learner with randomized labels):

On this dataset, the X-learner assigns positive but near-zero uplift scores to nearly all customers (consistent with AUUC = 0.0475). The cumulative margin curve Π(k) is therefore monotonically non-decreasing — no customer has a negative estimated uplift — and no interior optimum exists. This confirms that the profit-weighted Qini does not identify a targeting cutoff on null-treatment data; its value as a tool emerges on datasets with genuine heterogeneous treatment effects, where some customers have τ̂ < 0 and the curve peaks before 100%.

The 0 broadcast result from the full pipeline (Section 6.1) is consistent with this: the CFO Guardrail applies the stricter τ̂ × gross_margin − promo_cost > 0 check, which all customers fail when τ̂ ≈ 0 and promo_cost > 0. The two calculations are complementary — the Qini curve diagnoses rank quality; the Guardrail enforces the financial dispatch constraint.

Implementation note: The profit-weighted Qini curve has been defined and the formula implemented in budget_optimizer.py via the bang_per_buck ordering. Numerical Dataset 1 results from a standalone Qini-curve computation script are not available in the current codebase; the figures reported in an earlier draft were produced by a script that has since been removed. Full profit-weighted Qini curve plots will be reported in the forthcoming field study evaluation.

Business interpretation. In a live deployment on data with genuine treatment heterogeneity, the profit-weighted Qini curve will peak at an interior fraction strictly less than 100%, identifying the precise cutoff above which additional targeting is ROI-negative. Targeting the top k*k^*% by uplift score rather than broadcasting to all customers or relying on RFM rank alone is the mechanism by which the pipeline produces the per-dataset Δprofit improvements reported in Section 6.10.3. This optimal fraction directly informs Layer 4’s dispatch threshold: the pipeline suppresses campaigns for customers ranked below k*k^*, ensuring that only customers for whom expected incremental profit is positive after promo cost deduction receive an offer. When the forthcoming field study provides causally identified A/B labels, the profit-weighted Qini will serve as the primary business-value metric for model selection and threshold calibration.

AUUC formula methodological note: The standard Qini formula requires that the random baseline be normalized by the treatment/control ratio. When treatment rate ≠ 0.5, the naive formula (treating the random baseline as a straight diagonal line from origin to total converted) produces a floor of approximately −0.15 even for random models, because the unnormalized diagonal does not match the actual random targeting curve. The corrected formula used throughout this paper defines the random baseline as a straight line from 0 to the population ATE scaled by sample size:

random baseline endpoint=(∑iYiTiNT−∑iYi(1−Ti)NC)×N\text{random baseline endpoint} = \left(\frac{\sum_i Y_i T_i}{N_T} - \frac{\sum_i Y_i (1-T_i)}{N_C}\right) \times N

where NTN_T and NCN_C are treated and control counts respectively, and N=NT+NCN = N_T + N_C. This normalization ensures that a model with no discriminative power (random ordering) produces AUUC = 0 regardless of treatment rate, making AUUC values comparable across datasets with different treatment fractions. All AUUC figures reported in this paper use this corrected formula.

7. Discussion

7.1 The Declarative Rule Engine as Architectural Progress

The most significant architectural change in this iteration is the redesign of Layer 4’s decision logic from an imperative priority-ordered chain to a declarative two-step engine. The original design’s monolithic if/elif block encoded both control logic (which customers qualify) and financial validation (whether the action is profitable) in a single function, creating several maintenance liabilities: adding a new campaign type required modifying the control flow; testing required tracing through nested conditions; and the financial viability check was applied uniformly to all customers regardless of segment type.

The declarative engine resolves these issues by separating concerns. Business rules are expressed as data structures in action_rules.py, inspectable and modifiable without touching evaluation code. Financial validation is encoded in two purpose-built functions (_viable and _viable_loyalty) that reflect a deliberate policy distinction: persuadable customers are held to a stricter standard than rescue or sure-thing customers. The matches() function tests rules against customer context in a single pass, making the rule set auditable. This design is consistent with established software engineering principles for reducing technical debt in ML systems [16].

The practical effect is visible in the dessert-ml.csv send rate progression: the declarative engine with rescue logic and _viable_loyalty accounts for the largest single-upgrade jump (~10–15 percentage points), confirming that a significant fraction of the original suppressed population consisted of high-value customers blocked by an overly conservative uniform financial check.

7.2 The Two-Viability-Function Design as Financial Policy

The distinction between _viable and _viable_loyalty encodes a nuanced financial policy that the original single-check design could not express. For persuadable customers, the financial case for a campaign rests on the incremental revenue it generates above the customer’s baseline conversion probability. For sure-thing and rescue customers, the financial case rests on a different calculation: the cost of losing the customer’s future lifetime value versus the cost of the promotion.

This distinction matters empirically. Under the original design, a Can’t Lose Them customer with mildly negative uplift (e.g., −0.06) and high baseline conversion (e.g., 0.65) would be blocked by the do_not_disturb guard regardless of their historical spend. Under the new design, the rescue tier override reclassifies this customer as persuadable with rescue=True, the _viable_loyalty check passes (baseline_profit − promo_cost > 0), and a VIP Win-Back action is dispatched. The promotion is financially sound on a lifetime value basis even though the per-interaction incremental profit is mildly negative.

7.3 The IBM 10-Segment Standard as Interpretability Bridge

Adopting IBM 10-segment names as cluster labels — via rank-percentile normalization — provides an interpretability bridge between the statistical clustering output and the operator’s mental model. A business owner who understands intuitively that “Champions” need appreciation rather than discounts, and that “Can’t Lose Them” customers are worth aggressive spend to retain, can read the Layer 5 executive report without needing to understand K-Means geometry or silhouette scores.

The rule-based flags complement the K-Means names by guaranteeing that rare-but-critical states always appear in the segment list. In a large dataset with a small proportion of truly new customers, K-Means may assign those customers to a “Promising” cluster because they are most similar in RFM space to low-frequency recent buyers; the New Customer flag overrides this classification based on a direct recency + frequency threshold, ensuring the welcome offer logic applies. This hybrid design — statistical clustering for the bulk of the population, deterministic rules for edge cases — is a practical pattern for production systems where certain customer states require guaranteed handling regardless of training data coverage.

7.4 The CFO Guardrail as Organizational Boundary Automation

The most significant novel contribution of this framework is architectural: the placement of a financial constraint validator inside the ML decision loop rather than as a downstream organizational review step.

Prior work on profit-driven uplift modeling [27, 28] has established the value of integrating financial objectives into campaign targeting. Gubela et al. [27] and Devriendt et al. [28] show that incorporating revenue and cost structure into the uplift optimization objective improves financial outcomes over pure response-probability targeting. Our CFO Guardrail extends this direction by implementing financial validation as a hard constraint — rather than a soft objective — enforced per customer at inference time, and exposing all cost parameters through a single operator-editable configuration file.

In conventional enterprise deployments, data science teams generate recommendations reviewed by finance or marketing operations before deployment. This creates latency (typically days to weeks in SME contexts where reviews are informal), organizational friction, and the risk that financially sound recommendations are delayed or discarded for non-quantitative reasons.

By parameterizing financial constraints — COGS rate, margin floor, discount rates — and applying them per customer at inference time, the system eliminates the review step for routine campaigns. Edge cases surface naturally through the Do Nothing classification rather than requiring human escalation. The business_config.py file serves simultaneously as the operator’s financial policy document and the system’s decision boundary, creating a direct and auditable link between business rules and campaign outputs.

The ablation result (Section 6.10.4) quantifies this contribution empirically: the full pipeline — including the CFO Guardrail — produces $3,207 in Dunnhumby incremental Δprofit by converting a −$262 broadcast-all scenario into a net-positive outcome, consistent with the Guardrail being a key mechanism preventing money-losing campaigns.

7.5 Dynamic Cluster Selection as SME Adaptation

The results across both datasets illustrate why hardcoding cluster count is inappropriate for SME deployment contexts. The restaurant dataset (200 customers, dense repeat-visit behavior) produces optimal k = 2 with silhouette = 0.679; the Marketing Campaign dataset (905 customers, aggregate-level data) produces k = 3 with silhouette = 0.306. A system that hardcoded k = 3 for the restaurant dataset would artificially split a naturally binary customer structure, while hardcoding k = 2 for the marketing dataset would collapse meaningful behavioral distinctions.

The dynamic selection procedure, selecting k by maximizing silhouette score over k ∈ {2,…,10}, automatically scales granularity to data density. This is a key enabler of the minimal-input design principle: operators do not need to tune segmentation parameters.

7.6 Accessibility versus Accuracy Trade-offs

The framework makes deliberate simplifications to maintain accessibility. These trade-offs are transparent:

Inventory estimation from sales velocity introduces estimation error in the absence of live stock feeds — typical for SME POS systems. Operators with inventory management systems can replace the velocity-based estimator with direct stock queries through the stock_restock_cycle_days and stock_buffer_multiplier configuration parameters.

Treatment labels derived from the generator’s randomized assignment in Dataset 1, and from observational campaign acceptance records in Dataset 2 — both requiring caution in causal interpretation as discussed in Sections 4.4.1 and 5.1 — is a necessary concession for SME settings where historical A/B data is unavailable. The 5% ongoing control group enables proper causal measurement going forward, converting the system from a batch estimator into an accumulating randomized experiment over time.

Local LLM inference (3B parameter model) produces adequate executive summaries at zero ongoing cost and with full data privacy, but may produce less nuanced analysis than larger hosted models. The structured output validation layer partially compensates by catching factual errors in segment names, customer counts, and profit figures.

7.7 Extensibility

The pipeline architecture is designed for vertical expansion. The six-column input schema is generic enough to accommodate any transactional business. The business_config.py central configuration enables parameter tuning without code changes. Planned extensions include:

  • Event-driven campaign prediction: Incorporating scheduled events (festivals, public holidays, promotional calendars) as Layer 3 context signals for pre-emptive campaign planning
  • POS-CRM-LINE integration: Connecting the pipeline output directly to LINE-based ordering and delivery systems, enabling automated campaign dispatch through existing customer communication channels
  • Multi-location aggregation: Pooling POS streams from multiple outlets with site-level context flags for chain operators
  • Service business adaptation: Mapping product_name to service SKUs for beauty, automotive, and professional services verticals

7.8 Budget Knapsack as Explicit Financial Constraint

The budget optimizer adds a second financial constraint layer operating at a different level than the CFO Guardrail. The Guardrail enforces per-customer margin and incremental profit floors — it eliminates individually unprofitable actions regardless of budget. The budget knapsack enforces a collective ceiling — it selects the highest-value subset once all individual decisions have been approved.

The two constraints are composable by design: the Guardrail runs first (eliminating loss-making customers), and the knapsack runs second (selecting the best subset of the survivors). This ordering matters: a naive knapsack over all customers (including unprofitable ones) would waste budget on customers who should not receive campaigns regardless of budget. The two-stage design ensures that budget is allocated only among customers where a campaign is financially warranted.

The diminishing marginal ROI property of the greedy selection is not merely a theoretical property — it encodes a practical business insight. The first ฿/$ 1,000 of campaign budget should go to customers where promo spend converts nearly 1:1 to incremental margin. The last ฿/$ 1,000 goes to borderline customers where the margin contribution is positive but thin. Operators who examine the bang-per-buck curve gain a direct read on whether their budget is appropriately sized for their customer base.

Implementation note: The budget knapsack works as designed but has not been evaluated against a real campaign with a fixed budget ceiling. Empirical validation is pending.

7.9 Pooled Learning vs One-vs-Rest for Multi-Treatment Uplift

The existing MultiTreatmentUpliftModel (one-vs-rest) fits separate X-learners for each treatment type, treating “received this treatment” vs “received anything else” as the binary treatment indicator. This design is statistically clean but inefficient: a customer who responds to discount offers and a customer who responds to loyalty points may share predictive features that one-vs-rest cannot exploit across models.

Pooled learning resolves this by encoding arm identity as part of the feature space. The tau (CATE) models learn a continuous function over (customer features, arm indicator), enabling the following signal-sharing patterns:

  1. Shared control outcome model (mu0): Since mu0 predicts E[Y | X, T=0] without arm features, it pools all control observations across arms — yielding 3× the control sample size relative to per-arm fitting.
  2. Cross-arm CATE regularization: The LightGBM regularization (reg_lambda, min_child_samples) in the tau models applies to the joint (X, arm) feature space, preventing overfitting to small-arm subpopulations.
  3. Arm-interaction features: The model can discover interaction patterns, e.g., “customers with high womens purchase history respond better to womens email” — a cross-arm pattern not representable in separate one-vs-rest models.

The 9% ATE calibration error on the Hillstrom RCT (vs 247% under proxy-label training on retail datasets) is the most significant result in this evaluation. It is not primarily a property of pooled learning vs one-vs-rest — it is a consequence of using true randomized labels on a different dataset; the comparison is not controlled for dataset. However, the pooled model’s Qini of 0.1215 on a balanced three-arm RCT provides an important reference point: this is the quality achievable when genuine randomization is available, establishing a performance ceiling that proxy-label models are expected to approach as real campaign response data accumulates.

7.10 Limitations and Future Work

Evaluation on synthetic data: Dataset 1 is synthetically generated from known segment parameters. The silhouette score (0.679) and k=2 selection reflect the generator’s structure rather than discovering latent behavioral segments in real transaction data. Deterministic multi-seed convergence confirms the 200-customer dataset is too small for variance quantification. Evaluation on real pilot deployment data is the critical next step.

Uplift model AUUC on randomized labels: Apples-to-apples AUUC evaluation on Dataset 1’s actual randomized is_treated labels yields T-learner = 0.0612 and X-learner = 0.0475 — both near-zero, the statistically correct result when no true treatment effect exists. The previously-reported T-learner AUUC of 0.2351 was computed on proxy labels (was_treated = rfm_decile_segment ≥ median), which correlate with training features by construction and inflate apparent discriminative ability. The corrected values are reported in Section 6.10.1. AUUC on causally identified holdout data from a live A/B deployment remains the most informative evaluation and will be reported in the forthcoming field study.

Resolved: proxy label feature leakage (v1.15). An earlier proxy label implementation derived was_treated = rfm_decile ≥ median and converted = frequency > 1, then used rfm_decile_segment and frequency as model input features — producing circular training. This was identified as a significant defect and corrected in v1.15: proxy labels now use a temporal-split design (converted = retention in final 25% of observation window; random treatment assignment), and proxy-mode features are restricted to basket-level signals that do not participate in label construction. UK retail proxy broadcast count corrected from 63 to 19; Δprofit corrected from $40,630 to $2,529. See Section 4.4.1.

Resolved: uncalibrated base learner probabilities (v1.15). Resolved: LLM hard dependency (v1.15). The import ollama statement at module level caused ModuleNotFoundError on machines without Ollama installed, crashing the entire pipeline at import time. Fixed by lazy import with a structured template fallback. See Section 4.5.

Resolved: A/B holdout feedback loop (v1.15). The holdout_evaluator.py module now ingests post-campaign outcomes and exports retrain-ready labeled data. The remaining gap is that no real campaign has yet been deployed and measured — causal AUUC from a live holdout remains forthcoming.

Uplift evaluations in Datasets 1 and 2 rely on synthetic or no-control-group data: Dataset 1 uses treatment labels generated by a synthetic simulator — treatment effect is by construction null, and AUUC correctly converges to near-zero. Dataset 2 (marketing_campaign.csv) has no control arm: all 2,240 households were contacted (Z_CostContact = 3 uniformly), making it structurally impossible to train or evaluate uplift from this source alone. Uplift estimates on Dataset 2 reflect customer acceptance propensity, not incremental treatment effect. The Dunnhumby real-data retraining methodology (Section 4.4.2) directly addresses this limitation by providing a genuine natural treatment/control split (1,584 treated / 916 control) and doubly-robust evaluation to correct for the observed 4.7× pre-campaign spend differential between groups.

Observational labels in Dataset 2: Marketing campaign acceptance (AcceptedCmp) reflects customer self-selection, not randomized assignment. Uplift estimates from Dataset 2 are observational and subject to confounding. They should not be interpreted as causal effects.

Baselines gap on small dataset: Dataset 1 (synthetic restaurant, 200 customers) produces 0 broadcast and Δprofit = ฿0 under the X-learner with correctly randomized labels — zero broadcast validates model calibration on a null treatment effect. The T-learner baseline produces ฿2,162 (+0.3% vs broadcast-all ฿2,109), but this result used proxy labels (was_treated = rfm_decile ≥ median), not the randomized is_treated column; under correctly randomized labels, the T-learner AUUC also collapses to 0.0612 (Section 6.10.1). The material differential appears in the comparison to RFM-only (−฿1,334 vs ฿2,162 T-learner under proxy labels), confirming that the guardrail and uplift model together prevent money-losing campaigns.

Context layer — validated on engineered dataset, pending real POS confirmation: The velocity-based stock estimator showed no effect on Datasets 1–4, all of which lacked sufficient demand variability to trigger stockout conditions. Dataset 5 (synthetic Layer 3 test) confirms that the architecture functions correctly when demand surges occur: all 3 engineered stockout products are correctly flagged in_stock = False, and 23 customers (4.6%) are blocked from campaign dispatch as a result (Section 6.5). The remaining open question — whether Layer 3 produces material suppression rates on real POS streams with genuine seasonal demand spikes — will be addressed in the production field study.

Association rule lift: Lift values in the synthetic dataset reflect structured menu co-purchase patterns by construction. Real-world deployment is expected to produce lower but more actionable lift values as order diversity increases.

BG/NBD convergence on high-frequency retail: The CLV rescue tier implementation (Section 4.4.9) exposes a known limitation of the BG/NBD survival model: the optimizer fails to converge on daily/weekly purchasing datasets (dessert bakery, grocery retail) where customer dropout rates are near zero and transaction rates are very high. This is a fundamental BG/NBD characteristic, not a code defect — the model assumes a relatively low-frequency, non-contractual relationship with observable churn periods. For bakery and grocery contexts, an alternative survival specification (shifted-beta-geometric for contractual settings, or a simple recency-decay heuristic calibrated to observed churn rates) may provide more reliable CLV estimates. Until that alternative is implemented, _viable_clv falls back to _viable_loyalty, preserving current behavior.

Future work will examine: (1) real pilot deployment data from partner restaurant operators with 5% control groups; (2) online learning to update RFM and uplift models continuously; (3) multi-armed bandit formulations for campaign action selection with exploration-exploitation tradeoffs; (4) Qini-curve-based uplift objective integration to replace the current net-margin floor with a continuous financial objective in the LightGBM training loss; (5) alternative CLV survival models (Pareto/NBD, recency-decay heuristics) suited to high-frequency retail; (6) integration of pooled multi-treatment CATE estimates into the declarative rule engine’s action selection, enabling per-arm offer type routing based on model-predicted best treatment.

7.11 Expected Production Performance

The gap between model-estimated performance and realized production outcomes is a critical consideration for practitioners evaluating whether to deploy the framework. This section provides an honest, structured forecast grounded in the known limitations of each pipeline component.

What is expected to transfer reliably to production:

Segmentation quality — Layer 1 silhouette scores are computed on actual transaction data and reflect genuine cluster structure in the input distribution. Segment assignments will be consistent with the patterns observed across datasets. The dynamic k selection has demonstrated stable behavior across four structurally different datasets (k ∈ {2, 3}) and is unlikely to degrade on a new POS export from the same business vertical.

CFO Guardrail direction — The fundamental logic is sound regardless of label quality: customers who purchase at high baseline frequency generate near-zero incremental revenue from a promotion while incurring its full cost. The guardrail’s function of blocking these customers is expected to hold in production. The scaling pattern observed across datasets (guardrail savings grow with customer base size) is consistent with this mechanism.

broadcast_list.csv accuracy — With a real CRM providing verified customer IDs, the join between pipeline decisions and the customer database will be exact, eliminating the proxy-matching approximations present in the public dataset evaluations.

What will likely transfer with attenuation:

Uplift model rankings — The current model is trained on observational or proxy labels, producing rankings that reflect purchase propensity rather than causally identified treatment response. In production, the model will continue to rank customers in the correct directional order — high-uplift customers will tend to respond more to campaigns than low-uplift customers — but the magnitude of the estimated uplift scores will likely be inflated relative to the true causal effect. Empirical evidence from the uplift modeling literature [12] suggests that observational uplift estimates typically overstate realized incremental lift by a factor of 1.5–3×.

Estimated incremental profit figures — The model-estimated improvements reported in this paper (+1,325% on Dunnhumby under X-learner; UK pipeline vs. broadcast-all comparison not reported under temporal-split proxy labels — see Section 6.6) are model-estimated projections on observational or proxy labels and should be treated as upper bounds rather than production expectations. A realistic range for the first deployment cycle, based on industry benchmarks for campaign personalization at comparable scales, is +20–50% improvement in campaign ROI vs. naive broadcast. This range accounts for: (a) attenuation from observational label bias; (b) real-world behavioral variance not captured by the model; and (c) novelty effects that inflate early campaign response rates before settling to steady state.

8. Conclusion

This paper presented the ML Campaign Engine, a five-layer MLOps pipeline that enables small and medium enterprises in retail and food service to generate financially validated, per-customer campaign recommendations from standard POS transaction exports. The system requires no dedicated data science expertise, no additional data infrastructure beyond an existing POS system, and produces outputs in plain-language executive summary format suitable for direct operator consumption.

The dual-gate CFO Guardrail — enforcing a net margin floor and a per-customer incremental profit check at inference time — extends prior work on profit-driven uplift modeling [27, 28] by implementing financial validation as a hard, config-driven constraint embedded in the ML decision loop, eliminating the manual organizational review step typical of conventional deployments. Pipeline comparisons and ablation analysis are consistent with the CFO Guardrail being a key mechanism preventing money-losing campaigns: on Dunnhumby, the X-learner pipeline produces $3,207 in incremental Δprofit against a broadcast-all baseline of −$262 — a +$3,469 swing consistent with the guardrail suppressing negative-ROI campaigns. Ablation analysis (Section 6.10.4) further confirms that removing the guardrail on Dataset 1 produces −฿533 in money-losing campaigns that the guardrail correctly prevents.

The uplift model has been upgraded from the T-learner baseline (prior reported AUUC = 0.2351 on Dataset 1 was inflated by proxy label bias; corrected value on randomized labels = 0.0612; X-learner AUUC on randomized labels = 0.0475) to an X-learner meta-learner (Künzel et al. 2019, n_estimators = 200), which trains five LightGBM models through a two-stage imputation procedure that better handles the treatment/control group imbalance typical of SME deployments. Additionally, a purpose-built Layer 3 synthetic test dataset (Dataset 5, 500 customers) validates the context detection layer’s stockout suppression: all three engineered demand-surge products are correctly flagged out-of-stock, and 23 customers (4.6%) are blocked from campaign dispatch — confirming that the previously-reported zero Layer 3 effect was a dataset limitation and not an architectural one.

Evaluation across seven datasets confirms context-appropriate behavior and a consistent scaling pattern. The synthetic restaurant dataset (200 customers) yields k = 2 with silhouette = 0.679, X-learner AUUC = 0.0475 on correctly randomized labels (near-zero as expected; T-learner AUUC = 0.0612 — both corrected from prior inflated proxy-label value of 0.2351; see Section 6.10.1). The T-learner under proxy labels marginally outperforms naive broadcast (+0.3%, ฿2,162 vs ฿2,109), but this figure uses proxy labels and is not causally interpretable. The Dunnhumby grocery dataset (2,500 customers) yields k = 3 with silhouette = 0.595. With the X-learner uplift model, the full pipeline outperforms broadcast-all by +1,325% in model-estimated incremental profit ($3,207 vs −$262.05, 72/2,500 broadcast). Notably, X-learner approves 63/506 Champions based on genuine incremental response signal from real campaign data, while suppressing the remaining 443/506 Champions as purchasing regardless of promotions — concentrating broadcast on those with genuine incremental response. The UK Online Retail dataset (4,338 customers) yields k = 2 with silhouette = 0.931. Under temporal-split proxy labels (corrected from RFM proxy with feature leakage), the X-learner pipeline approves 19 customers for broadcast (Δprofit = $2,529). Under synthetic treatment labels (post-hoc), 3,581 customers are approved (Δprofit = $55,324) — the ~188× range validates that label fidelity is the primary driver of broadcast volume rather than architectural conservatism. Dynamic cluster selection correctly adapts across all data structures. All six stress-test scenarios pass quantitative criteria. The scaling pattern — pipeline advantage grows from +0.3% at n=200 (T-learner baseline; the X-learner produces 0 broadcast on correctly randomized labels, validating calibration) to +1,325% at n=2,500 — is consistent with the hypothesis that guardrail value compounds as the fraction of near-zero-uplift customers increases. All profit figures are model-estimated projections; causal validation requires the forthcoming real-world field study.

Honest limitations include the small synthetic dataset, deterministic model convergence at n=200, and the absence of real pilot data. All profit figures reported in this paper are model-estimated projections on synthetic or public datasets — they represent the system’s designed behavior under controlled conditions, not realized revenue outcomes from live campaigns.

Research Roadmap: Real-world profit impact will be measured in a forthcoming field study conducted with a CRM-integrated POS operator, incorporating randomized holdout control groups (Treatment / Control split) and realized profit attribution across full campaign cycles. That study will provide the first causally interpretable evidence of whether the pipeline’s financially validated recommendations produce measurable incremental revenue above the no-campaign baseline.

Three extensions further the framework’s financial rigor and modeling capability. A budget-constrained knapsack optimizer (budget_optimizer.py) selects the profit-maximizing subset of CFO-approved customers within an operator-specified spend ceiling, using greedy bang-per-buck ordering that is provably optimal for the fractional knapsack and achieves a 1/2-approximation for the 0/1 knapsack via max(greedy result, best single item) ≥ ½ × OPT (implementation complete; empirical validation against a real fixed-budget campaign is pending). A CLV-informed rescue tier viability function (_viable_clv) conditions rescue campaign approval on promo_cost ≤ clv_at_risk estimated from BG/NBD survival modeling — replacing the heuristic _viable_loyalty check with a financially grounded justification; fallback to the heuristic is automatic when BG/NBD fails to converge on high-frequency datasets (BG/NBD falls back to heuristic on all tested datasets; empirical CLV results are pending). Finally, a pooled multi-treatment uplift model (PooledMultiTreatmentModel) trains a single X-learner with treatment arm as one-hot features, evaluated on the Hillstrom MineThatData RCT: Qini = 0.1215, AUUC = 0.0614, ATE calibration error of 9% on the Hillstrom RCT — substantially lower than the 247% error observed under proxy-label training on retail datasets, where the absence of true randomization inflates apparent ATE discrepancy. This confirms that true RCT data substantially improves model reliability, though the comparison reflects both better labels and a different dataset.

The framework establishes a reproducible, extensible baseline for democratizing campaign intelligence for SMEs, and provides a validated technical foundation for the real-world A/B deployment that will constitute the critical next phase of evaluation.

Appendix C — Declarative Rule Engine Design Summary

The declarative rule engine (src/action_rules.py) defines the full action menu as two Python lists of dicts. The evaluation logic in src/uplift_engine.py calls matches() and either _viable or _viable_loyalty for each rule without knowledge of the specific rule contents. This separation enables:

  1. Adding a new campaign type by appending a dict to SURE_THING_RULES or PERSUADABLE_RULES with the appropriate tier, context, rfm_min, and rate_key fields — no changes to evaluation code required.

  2. Auditing the rule set by reading the list data structure directly — no control flow tracing required.

  3. Testing individual rules by constructing a mock customer context and calling matches() on a single rule dict.

The cluster_tier() function maps IBM segment names (including rule-based flag names) to the tier strings used in rule tiers lists. It checks flag-name prefixes first (priority overrides: can't lose, churn risk, new customer, about to sleep) before IBM K-Means labels, ensuring suffixed duplicates like “Champions (2)” map correctly to “champions” via startswith prefix matching.

The evaluation strategies are:

Rule pool Strategy Viability function
SURE_THING_RULES First viable rule wins (list order) _viable_loyalty
PERSUADABLE_RULES Collect all viable, return max profit _viable (or _viable_loyalty if rescue=True)

The rescue flag is set to True by decide_for_customers() when the customer’s tier is in {churn_risk, cant_lose, hibernating, about_to_sleep} and their uplift falls in the do_not_disturb range but above the rescue_uplift_guard threshold (−0.10). The flag is passed into build_action_menu(), which selects the viability function accordingly.

The two viability functions implement the CFO Guardrail at the per-rule level:

  • _viable(rate_key): requires net_margin ≥ MIN_MARGIN AND incremental > 0. Used for persuadable customers where the campaign must generate more revenue than it costs at the margin.
  • _viable_loyalty(rate_key): requires baseline_profit − promo_cost > 0. Used for sure-thing and rescue customers where the financial case is lifetime value preservation, not per-interaction incrementality.

This two-function design means the guardrail applies appropriate standards to each customer type rather than a one-size-fits-all check, enabling the pipeline to serve the full range of IBM customer archetypes while maintaining financial discipline.
