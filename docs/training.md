# เทรนและอนุมัติ Champion (Training / Serving)

ออกแบบ: `docs/superpowers/specs/2026-11-03-training-serving-design.md`

หลักการ: **การรัน pipeline รายเดือน (Serving) ใช้ Champion ที่อนุมัติแล้วให้คะแนนอย่างเดียว ไม่เทรน** ส่วนการเทรน
เป็นคำสั่งแยก ทีม ML สั่งเอง ผลคือ "ผู้สมัคร" (Candidate) ที่ต้องมีคนกดอนุมัติบนหน้าเว็บก่อนจึงจะเป็น Champion

## ครั้งแรก (ทำครั้งเดียว)
```bash
python src/train_champion.py --import-legacy    # นำ models/registry/champion_xlearner.pkl เดิมเข้าทะเบียนเป็น v1
```
v1 ติดป้าย provenance = `simulated` (เทรนจากข้อมูลจำลอง) และใช้งานต่อจนกว่าจะอนุมัติรุ่นใหม่ ถ้าไม่ทำขั้นนี้
`csv_pipeline_engine.py` จะหยุดพร้อมข้อความบอกให้ทำ

## เทรนผู้สมัคร (สั่งมือ)
```bash
export CRM_API_PUBLIC_URL=http://localhost:8000          # ใช้สร้างลิงก์ที่พิมพ์ตอนจบ
python src/train_champion.py \
  --store-data shop-a:data/a.csv:data/a_labels.csv \     # <store_id>:<csv>[:<ไฟล์ label โปรจริง>]
  --store-data shop-b:data/b.csv:data/b_labels.csv \
  [--holdout-frac 0.2] [--seed 42]
```
- รวมข้อมูลทุกร้านที่ระบุ (ลูกค้า = คู่ร้าน+รหัส ไม่ปนกัน) กันลูกค้า 20% ไว้ประเมิน (holdout) แล้วเทรนจากส่วนที่เหลือ
- ทุกร้านต้องใช้ label ชนิดเดียวกัน (มีไฟล์ label ทั้งหมด หรือไม่มีเลย) ไม่งั้นหยุดและบอกว่าร้านไหน
- ไม่มี label โปรจริง → ระบบสร้าง label ประมาณการ (proxy) หน้าอนุมัติจะเตือนว่า **ไม่ใช่หลักฐานว่าโปรได้ผลจริง**
- ตอนจบจะพิมพ์ลิงก์ `…/v1/models/candidates/<id>?token=…` (ต้องเปิด CRM API ไว้)

## อนุมัติ
เปิดลิงก์ในเบราว์เซอร์ → ดูเปรียบเทียบ Champion/Challenger → กรอกชื่อผู้อนุมัติ → กด **อนุมัติ** หรือ **ไม่อนุมัติ**
- อนุมัติ: Champion เดิมถูกเก็บใน `models/archive/` แล้วแทนด้วยตัวใหม่ (เขียนแบบ atomic) และบันทึกใน `output/pipeline_audit.jsonl`
- ผู้สมัครที่เทียบกับ Champion รุ่นที่ไม่ใช่ปัจจุบันแล้ว (มีคนอนุมัติตัวอื่นก่อน หรือเพิ่ง rollback) จะ **ล้าสมัย** อนุมัติไม่ได้ ต้องเทรนใหม่
- ลิงก์มี token ใครมีลิงก์ก็ตัดสินผู้สมัครนั้นได้ token อยู่ใน URL (อาจติด log/ประวัติ shell) จึงเปิดบริการเฉพาะเครื่องตัวเอง (localhost) ไว้ก่อน
- routes เหล่านี้ไม่อยู่ใน `/docs` (เป็นเครื่องมือของผู้ดูแล ไม่ใช่ส่วนของสัญญากับ CRM)

## ใช้งานรายเดือน (Serving)
```bash
python src/csv_pipeline_engine.py <transactions.csv>     # ให้คะแนนด้วย Champion ปัจจุบัน ไม่เทรน ไม่แตะ models/
python src/campaign_scheduler.py --month 2026-12
```
รุ่นที่ใช้บันทึกไว้ใน `data/processed/model_used.json` ถ้าไม่มี Champion, ไฟล์ Champion ถูกแก้ (sha256 ไม่ตรง) หรือฟีเจอร์ของข้อมูล
ไม่ตรงกับที่เทรน จะหยุดพร้อมข้อความระบุสาเหตุ (ไม่เทรนแทน)

## ย้อนกลับ
```bash
python src/train_champion.py --rollback v1
```

## ข้อควรระวัง
- ตัวเลขกำไรในหน้าอนุมัติใช้ต้นทุนสินค้า (COGS) ค่าเริ่มต้น จึงไม่ตรงกับตัวเลขในแผนส่งโปรรายเดือน แต่ใช้เทียบสองโมเดลได้เพราะวัดเกณฑ์เดียวกัน
- สถิติรวม (RFM, เกณฑ์ราคา) คำนวณจากข้อมูลทั้งไฟล์เหมือนตอนใช้งานจริง ไม่ได้แยกเฉพาะชุดเทรน
- รวมข้อมูลหลายร้านเข้าเทรนเป็นเรื่องสิทธิ์การใช้ข้อมูล (ผู้ใช้ระบบรับผิดชอบ) ระบบบันทึกแค่ว่ารอบไหนใช้ร้านไหน
  และโมเดลที่เรียนรู้ไปแล้ว "ลืม" ร้านที่ออกไปไม่ได้ ได้แต่ไม่ใช้ข้อมูลร้านนั้นในรอบถัดไป
- ไฟล์ในทะเบียนเป็น pickle: อย่าเปิดช่องให้อัปโหลดไฟล์เข้า `models/`
